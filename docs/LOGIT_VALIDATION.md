# Full-logit validation

`--logits-file` writes raw model output scores for every vocabulary entry at every teacher-forced continuation step. It is an opt-in diagnostic for `strata-poly` one-shot text runs. It does not prove equivalence on its own; run both configurations with the same model, token IDs, context and numerical settings, then compare the files. Keep the model checksum, executable revision, command lines, environment and hardware with the results. The file records token IDs and dimensions, not model identity or execution settings.

Provide a nonempty prompt and nonempty forced continuation, and set `--max-new` to exactly the continuation length. This example compares two independently configured executables; the tolerance values are illustrative, not acceptance criteria:

```sh
STRATA_ROUTE_TAIL_SKIP=0 ./reference/strata-poly --model model.gguf --tokens-file prompt.txt --follow-file continuation.txt --max-new 3 --logits-file reference.bin
STRATA_ROUTE_TAIL_SKIP=0 ./candidate/strata-poly --model model.gguf --tokens-file prompt.txt --follow-file continuation.txt --max-new 3 --logits-file candidate.bin
python tools/compare_logits.py reference.bin candidate.bin --atol 0.001 --rtol 0.001
```

Here `continuation.txt` must contain exactly three comma-separated token IDs. The first row predicts its first ID after the complete prompt; each later row predicts the next ID after appending all earlier forced IDs. EOS does not stop this diagnostic. Lookup and draft speculation are disabled for this mode, so no speculative or discarded rows enter the file. The ordinary generation path is unchanged when the option is absent. Text only; serve mode, images and batch checks are rejected. Existing integration policy rejects expert skipping; neither diagnostic nor comparator changes expert weights.

The comparator requires identical vocabulary size, number of steps, prompt IDs and forced IDs, and rejects invalid dimensions, out-of-range IDs, non-finite scores, truncated files and trailing bytes. For each value it checks `abs(candidate - reference) <= atol + rtol * abs(reference)`; both tolerances are mandatory, finite and nonnegative. It reports the count outside tolerance, maximum absolute error, RMS error, top-1 agreement count, and mean per-step KL divergence `KL(softmax(reference) || softmax(candidate))`. These additional statistics are descriptive; only the elementwise check determines numeric pass/fail. Exit status is 0 for a pass, 1 for a numeric mismatch, and 2 for invalid input. Top-1 agreement alone is not numerical validation. Select tolerances in advance based on the actual comparison and use a separate independent reference where possible.

The binary format is little-endian: eight bytes `SAGELOG1`, then four uint32 fields (version 1, vocabulary size, prompt count, step count), followed by prompt IDs and forced IDs as int32, then `steps * vocab` IEEE-754 binary32 values in step-major order. Prompt count and steps are each 1–1,000,000 and vocabulary size is 1–10,000,000. A failed or interrupted run can leave an incomplete file; check its exit status and let the comparator reject it.

The pinned PolyStrata [engine interface](https://github.com/VecSzn/PolyStrata/blob/52c31cfcb55d7e42506a57757886af73f9547314/src/poly/engine.hpp#L206-L209) describes logits as the scores after the evaluated token; its [generation loop](https://github.com/VecSzn/PolyStrata/blob/52c31cfcb55d7e42506a57757886af73f9547314/src/poly/main.cpp#L403-L405) evaluates the last prompt token for those scores and [uses forced IDs](https://github.com/VecSzn/PolyStrata/blob/52c31cfcb55d7e42506a57757886af73f9547314/src/poly/main.cpp#L468-L471). The pinned llama.cpp [perplexity implementation](https://github.com/ggml-org/llama.cpp/blob/3cf03257f219afbe7334045ff7c6a06ac68c627d/tools/perplexity/perplexity.cpp#L60-L69) uses max-shifted log-softmax, and its [KL calculation](https://github.com/ggml-org/llama.cpp/blob/3cf03257f219afbe7334045ff7c6a06ac68c627d/tools/perplexity/perplexity.cpp#L191-L232) compares output distributions. Those diagnostics motivate the stable probability calculation here; llama.cpp's compressed probability format is different and is not directly readable by this comparator.
