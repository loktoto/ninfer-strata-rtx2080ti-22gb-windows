# IQ4_XS expert integration — 2026-10-30

An experimental opt-in NInfer-all-derived IQ4_XS expert slot kernel is linked into the Strata executable. `STRATA_SAGE_EXPERT_IQ4XS=1` selects it for eligible cached GPU IQ4_XS expert matrix-vector products; the default stays on native Strata. The strict launcher and API setup expose `--ninfer-expert-iq4xs`. They disable graphs and draft tokens. CPU experts, other weight types and Strata's separate prefill paths remain native. The candidate does not convert or own the model, allocate scratch, or run a second engine.

The decoder and two-rows-per-warp, 32-value-slice vector scheduling are adaptations of [NInfer-all `ggml_bridge_vec.cuh`, commit 71d3f819](https://github.com/iamwavecut/ninfer-all/blob/71d3f8190772ef7089f8eda4e22371114fd5bbf9/src/ops/linear/gguf/ggml_bridge_vec.cuh), Apache-2.0. The decoder combines its 6-bit subscale, 4-bit IQ codebook and FP16 block scale, and its dot uses Q8_1. The implementation is rewritten for Strata's interleaved Q8_1 blocks and borrowed expert slots; scalar codebook lookup replaces the donor's packed table and dp4a operations. The donor's planar activation layout and full MoE runtime are not imported. The dense Windows NInfer donor does not support this GGUF MoE path.

## RMSNorm remains unqualified

The earlier experimental NInfer-derived RMSNorm candidate passes a synthetic oracle but failed full-model comparison: 3,851,231 of 3,973,120 logits exceeded atol 1e-4 / rtol 1e-3, with maximum absolute difference 1.602 and RMS 0.212. Different reduction and rounding orders are plausible, not a proven root cause. It remains disabled by default; do not enable it for production. The IQ4_XS results above isolate the expert path with RMSNorm disabled. See [diagnosis](IQ4XS_UPLIFT_DIAGNOSIS_2026-10-29.md).
